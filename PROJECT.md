# Daemonarchy ports development

## Goals

- **PORT-G1:** Represent the complete owned ports tree through canonical origin
  and shared-support Components, exact original inputs and complete selected
  native dependency/variant relationships. Unselected origins remain visible.
- **PORT-G2:** Build, test and package real ports through the same installed
  Literate AI interface as the source fork, in the parallel native workspace.
  Preserve original make targets as the first bridge and measure executor
  alternatives against equivalent correct clean, warm and changed-input work.
- **PORT-G3:** Bind source/distfile identities and checksums, patches, shared Mk
  files, target/ABI, options, compiler/runtime resources and installed bootstrap
  tools explicitly. Changes must invalidate affected objects, test state and
  packages rather than trusting old ports completion cookies.
- **PORT-G4:** Produce actual versioned pkg artifacts with source/build
  provenance, both BOMs and typed dependencies for every selected unit. Preserve
  original licenses and actual tests; qualify independent sealed-product and
  disposable-VM installation/update/rollback acceptance.
- **PORT-G5:** Keep original upstream implementations and hierarchy, support
  regular reviewed upstream imports and contribute general fixes normally.
  Designate cut-over only after the shared Daemonarchy acceptance gates pass.

## Dependencies

The Daemonarchy product project owns workspace deployment, release/ISO composition
and cut-over. The source fork supplies the matching base/kernel and ABI.
The Literate AI framework owns retained native input custody, command execution,
test/independent acceptance, package consumers and installed CLI integration.
Metadata registration does not satisfy these executable dependencies.

make framework. This is a small real starting boundary, not complete ports
coverage or admitted execution. The product repository retains a direct native
make probe that built LZ4, ran its default upstream checks and created a pkg;
that probe is not a Literate AI lifecycle receipt or a qualified Component pkg.
Original-source adoption now records the clean Git tree without moving source.
The installed Standard binding selects framework revision `cffef3238ba48f2c0876270aa4a1aeacce4c86e1`
and its complete evidence policy. Project authority and both FreeBSD/pkg locks
validate through that installed CLI. Verification still fails on the missing
current test receipt. Exact native profiles, toolchain custody, original input
admission and installed target execution remain unfinished.
