# Daemonarchy ports development

Read `PROJECT.md`, [the documentation index](docs/README.md),
[the unit guide](docs/user/ports-units.md) and
[the active queue](docs/roadmap/active-work.md) before changing authority.
The original ports, Mk files, patches, distinfo and upstream tests remain
implementation authority. Keep them editable; do not quarantine or regenerate
them during adoption. Use review branches targeting `daemonarchy`; keep
upstream `main` separate.

Use canonical Components, selected native Flavors and current locks. Exact
original-source adoption and installed Standard binding require their reviewed
plan/apply transactions. They grant no native execution or package acceptance.
Do not copy a weaker evidence policy to obtain a passing receipt.

Use selected original make targets as the first native bridge, with isolated
objects, distfiles, options, staging and packages. Do not install build
dependencies on the live workstation as a side effect. Bind installed bootstrap
tools to observed versions and bytes; unknown source-build provenance stays
explicit. Preserve actual dependency and option constraints from native metadata.
Regular upstream imports must not require wrapper files throughout port origins.

Keep every original test result and explicit skip reason. Run independent
acceptance against sealed products. Fast unchanged returns from completion
cookies do not prove changed-input correctness. Native commands, package-format
checks and discovery inventories cannot substitute for admitted Component
execution, complete ownership, per-unit provenance or the release closure.
Preserve failed evidence and use only allocated aligned native workers.
